# Gun Tracker 稳定锁定、目标筛选与 HUD 重构设计

日期：2026-09-14

## 1. 背景与目标

当前版本已经具备透明设置面板、4 个触发快捷键、三种自瞄行为、TACZ 弹道预测、目标筛选和 HUD，但实际体验存在以下问题：

1. 三种自瞄模式差异不明显。当前默认参数下，平滑追踪速度接近 1.0，瞬间锁定直接使用 1.0，甩枪回正默认甩枪速度也为 1.0，因此视觉上非常接近。
2. 非瞬间模式的“平滑”目前主要依赖单 tick 内的重复旋转子步，并不是真正跨 tick 的阻尼追踪；目标预测点或实体运动数据轻微抖动时，视角会出现一卡一卡、抽搐或微振。
3. 当前锁定状态仍会定期扫描所有候选，并可能被评分更优的新目标抢走，导致多人或多怪场景下频繁换人。
4. 目标类型目前是单选枚举，无法让用户自由组合“玩家 / 敌对怪物 / 其他生物”。
5. 盔甲架、NPC、训练假人、伪玩家缺少明确过滤策略。
6. HUD 开关虽然存在，但用户无法方便地确认整个自瞄系统当前是开启还是关闭，且显示位置固定，缺少可拖动的常驻状态组件。

本次目标是在不推翻现有 TACZ 弹道解算和快捷键框架的前提下，重构四个核心区域：

- 稳定锁定状态机
- 三种有明确差异的自瞄行为
- 组合式目标筛选与防假人
- 可拖动常驻 HUD 与独立总开关键

## 2. 总体架构

本次采用“保留现有弹道核心，重构锁定与输出层”的方案。

保留：

- `TaczBallistics`
- `BallisticsMath`
- 现有弹速、摩擦、重力、提前量和动态校准机制
- 4 个自瞄触发槽位及其按住 / 切换 / 长按触发方式
- 300 方块最大搜索距离上限
- 透明设置面板与中英文语言资源框架

重构或扩展：

- `TargetSelector`：从“定期重新选最优目标”改为“锁定状态 + 候选确认 + 粘滞切换”
- `AimHandler`：从单 tick 直接旋转改为跨 tick 的模式化视角控制
- `TargetMotionTracker` / 输出角度：增加稳定化处理，降低预测点抖动向视角直接传播
- `Config`：加入组合目标筛选、防假人模式、粘滞参数、模式专属参数、HUD 位置与显示项
- `GunTrackerConfigScreen`：重新组织目标页、自瞄页和 HUD 页
- `AimHud`：改为常驻、可定位、可配置内容的状态组件
- `Keybindings`：增加独立的“总自瞄开关”快捷键

## 3. 稳定锁定状态机

### 3.1 核心原则

锁定后的当前目标拥有明显的粘滞优势，但不是永远无法切换。

系统维护：

- 当前锁定目标
- 当前候选替代目标
- 候选连续保持优势的 tick 数
- 当前目标不可见持续 tick 数
- 当前目标是否已超出脱锁范围

### 3.2 获取目标

当当前没有目标时：

1. 按目标类型过滤。
2. 按防假人规则过滤。
3. 按存活、移除状态、距离、搜索 FOV、可见性要求过滤。
4. 对剩余候选计算评分。
5. 选择最佳候选作为当前锁定目标。

### 3.3 锁定后的粘滞行为

锁定目标有效时，不再因为某一 tick 出现评分略好的实体就立刻切换。

新增 `粘滞强度`，范围 0～100，默认 85。

含义：

- 0：接近旧逻辑，较容易切换。
- 50：需要较明显优势才切换。
- 85：默认强粘滞，适合稳定跟踪。
- 100：除非替代目标长期明显更优，否则基本不主动换锁。

粘滞强度会影响新目标需要超过当前目标的最低评分优势。

### 3.4 切换确认时间

新增 `切换确认时间`，以 tick 为单位，默认 12 tick。

一个新候选只有在连续多个 tick 都满足“明显优于当前目标”时，才允许替换当前目标。

如果候选中途失去优势、离开范围或被过滤，确认计数立即清零。

这样可以过滤掉：

- 玩家从准星前一闪而过
- 两个目标位置短暂交叉
- 预测点一帧抖动导致的评分变化

### 3.5 当前目标失效

以下情况立即解除当前锁定并重新寻找：

- 目标死亡
- 目标实体被移除
- 目标超出最大锁定距离
- 目标不再符合用户启用的目标类别
- 目标被防假人规则判定为无效

以下情况允许短暂容忍：

- 暂时不可见
- 暂时离开搜索 FOV，但仍在更宽的脱锁 FOV 内

### 3.6 不可见容忍

新增 `不可见容忍时间`，默认 10 tick。

若启用了“仅可见目标”：

- 锁定前仍严格要求可见。
- 锁定后，目标短暂被墙角、实体或粒子遮住，不会立即丢锁。
- 连续不可见超过容忍时间后才解除。

### 3.7 搜索 FOV 与脱锁 FOV 分离

保留现有 `搜索 FOV`。

新增 `脱锁 FOV`，默认值应大于搜索 FOV，例如默认搜索 70°、脱锁 110°。

效果：

- 新目标必须进入搜索 FOV 才能被获取。
- 已锁目标可以在更宽的范围内继续保持锁定。
- 只有目标真正跑出脱锁 FOV 后才解除。

如果用户把脱锁 FOV 调得小于搜索 FOV，保存时应自动钳制为不小于搜索 FOV。

## 4. 三种自瞄模式重新定义

三种模式必须在默认参数下就有明显可感知差异，不能只依赖用户自己调速度。

### 4.1 平滑追踪（SMOOTH_TRACK）

定位：持续追踪、自然、稳定。

行为：

- 不再使用“同一个 tick 内重复 setYRot/setXRot”作为主要平滑手段。
- 每个客户端 tick 根据当前角度与目标角度的差值计算下一步。
- 使用跨 tick 阻尼 / 平滑系数逐渐逼近目标。
- 加入最大每 tick 转向角限制，避免目标预测点突变时瞬间猛甩。
- 允许用户调整：
  - 跟随速度
  - 阻尼强度
  - 最大转向速度

默认应明显慢于瞬间锁定，但仍足够跟得上普通移动目标。

### 4.2 瞬间锁定（SNAP）

定位：第一次抓到目标时快速甩准，之后稳定跟随。

行为：

- 从“无目标”进入“成功获取目标”的首个 tick，立即对准目标。
- 后续 tick 不再每 tick 强制瞬间重置到预测点。
- 后续跟随使用较高速度但带稳定化的追踪器。
- 当粘滞逻辑切换到一个新的目标时，该新目标视为一次新的获取，可再次执行首帧瞬间甩准。

这样 SNAP 和 SMOOTH_TRACK 的区别是“首次获取是否瞬间到位”，而不是两个参数接近 1.0 的连续模式。

### 4.3 甩枪并回正（FLICK_RETURN）

定位：快速甩到目标，释放触发后回到触发前视角。

行为：

- 触发开始时保存原始 yaw / pitch。
- 首次获取目标时快速甩准，速度独立于平滑追踪。
- 按住 / 激活期间继续使用稳定跟随，避免锁住后抖动。
- 触发结束后使用独立回正速度，平滑返回原始视角。
- 回正过程中不继续重新选目标。

### 4.4 角度输出稳定化

所有模式都经过统一的最终输出稳定化层：

1. 目标位置经过现有运动预测与弹道预测。
2. 预测结果转成目标 yaw / pitch。
3. 对最终 yaw / pitch 做短时平滑和异常跳变限制。
4. 再交给具体模式决定首帧行为和每 tick 转向量。

主要目的是避免预测点的一点点变化直接成为玩家视角抖动。

## 5. 组合式目标筛选

废弃仅依赖 `TargetMode` 单选枚举作为用户入口，改为三个可独立勾选的布尔类别：

- `锁定玩家`：默认开启
- `锁定敌对怪物`：默认开启
- `锁定其他生物`：默认关闭

“其他生物”包括不是玩家、也不是敌对 `Monster` 的其他 `LivingEntity`，例如动物、村民等。

设置页增加“全体可锁定实体”快捷操作：

- 全选：三个类别全部开启
- 全不选：三个类别全部关闭

如果三个类别全部关闭，自瞄不会获取任何新目标，但总开关本身可以保持开启。

非活体对象不纳入目标：

- 掉落物
- 箭
- 子弹
- 经验球
- 方块实体

## 6. 防假人 / 防盔甲架

新增枚举 `防假人模式`：

- `关闭`
- `标准过滤`
- `严格过滤`

默认：`标准过滤`。

### 6.1 盔甲架

盔甲架永远不作为自瞄目标，不受防假人模式影响。

原因：盔甲架通常被地图、服务器、模组作为展示物或假目标使用，几乎不属于合理枪械自瞄对象。

### 6.2 标准过滤

对普通生物不做额外处理。

对 `Player` 类型：

- 必须能通过当前客户端连接按 UUID 找到正常 `PlayerInfo`。
- 缺少正常玩家信息的 Player 实体视为 NPC / 假人并过滤。

该模式优先降低误判，适合作为默认。

### 6.3 严格过滤

在标准过滤基础上进一步过滤明显异常的 Player 实体。

严格模式可使用以下低风险信号组合，不依赖单一信号直接误判：

- UUID / GameProfile 信息异常或缺失
- 实体 UUID 与客户端正常玩家信息无法一致对应
- 玩家名为空、非法或无法与 PlayerInfo 对应
- 同一 UUID 出现多个互相冲突的 Player 实体
- 其他明确表明其不是正常网络玩家的资料异常

严格模式不使用“站着不动”“移动方式奇怪”等纯行为特征作为唯一过滤理由，以免把真实 AFK 玩家误判为假人。

严格过滤仍然无法保证识别所有模组 NPC 或服务器自定义假人，界面文案应明确它是更激进的启发式过滤，而不是百分之百检测。

## 7. 总开关键

新增独立 KeyMapping：`切换自瞄总开关`。

要求：

- 默认未绑定。
- 支持键盘和鼠标绑定。
- 在设置面板中可直接捕获按键 / 鼠标。
- Backspace 清除绑定，Esc 取消捕获。
- 按一下切换 `MASTER_ENABLED`。
- 关闭总开关时立即清除当前目标、候选切换状态和回正状态，防止残留控制视角。
- 再次开启时不会自动立即锁定，需等正常触发快捷键激活。

现有 4 个触发快捷键继续只负责“激活自瞄”，不负责总开关。

## 8. 常驻可拖动 HUD

### 8.1 总体行为

新增常驻状态框，默认始终显示，即使总开关关闭也显示。

默认内容：

- `自瞄：开启 / 关闭`
- `模式：平滑追踪 / 瞬间锁定 / 甩枪并回正`
- 有锁定目标时：`锁定：名称 距离`

例如：

```text
自瞄：开启
模式：平滑追踪
锁定：Steve 23.6方块
```

总开关关闭时至少显示：

```text
自瞄：关闭
```

### 8.2 独立显示开关

HUD 页增加：

- 显示状态框
- 显示总开关状态
- 显示当前模式
- 显示目标名称
- 显示目标距离
- 显示 FOV 圈
- 显示弹道信息

状态框位置与 FOV / 弹道信息可以独立处理。

### 8.3 可拖动位置

HUD 状态框支持用户自行移动。

推荐交互：

- 在 HUD 设置页提供“调整 HUD 位置”按钮。
- 进入 HUD 定位状态后，游戏画面上显示状态框预览。
- 鼠标左键拖动状态框到任意屏幕位置。
- 松开即保存归一化屏幕坐标。
- Esc 取消并恢复旧位置。

使用归一化坐标而非绝对像素，以适配不同 GUI 缩放和窗口分辨率。

默认位置：屏幕中心偏下，避免挡住准星本体。

## 9. 设置面板重新组织

### 9.1 总体页

保留：

- 自瞄总开关
- 当前自瞄模式
- 长按阈值

新增：

- 总开关快捷键绑定入口或提示

### 9.2 自瞄页

根据当前模式显示真正相关的参数。

通用：

- 角度输出稳定度
- 最大瞬时角速度 / 最大转向速度

平滑追踪：

- 跟随速度
- 阻尼强度
- 最大转向速度

瞬间锁定：

- 首次获取瞬间锁定（固定行为，不做无意义开关）
- 后续跟随速度
- 后续稳定度

甩枪并回正：

- 甩枪速度
- 持续跟随速度
- 回正速度

不再保留“看似存在但对当前模式无明显作用”的参数展示方式。

### 9.3 目标页

顺序建议：

1. 最大距离（4～300 方块）
2. 搜索 FOV
3. 脱锁 FOV
4. 仅锁可见目标
5. 玩家
6. 敌对怪物
7. 其他生物
8. 全体可锁定实体快捷操作
9. 防假人模式
10. 粘滞强度 0～100
11. 切换确认时间
12. 不可见容忍时间
13. 瞄准位置
14. 自定义瞄准高度

原来的“粘滞目标”布尔开关可以移除，因为新版锁定核心始终使用粘滞状态机；用户通过粘滞强度 0～100 控制实际效果。

### 9.4 HUD 页

显示上述所有独立显示开关，并提供：

- 调整 HUD 位置
- 恢复默认位置

## 10. 默认值

本次新参数默认值：

- 锁定玩家：开启
- 锁定敌对怪物：开启
- 锁定其他生物：关闭
- 防假人模式：标准过滤
- 粘滞强度：85
- 切换确认时间：12 tick
- 不可见容忍：10 tick
- 搜索 FOV：保留现有默认 70°
- 脱锁 FOV：110°
- 常驻 HUD：开启
- HUD 总开关状态：显示
- HUD 模式：显示
- HUD 目标名称：显示
- HUD 目标距离：显示
- 总开关快捷键：未绑定

模式默认值需保证肉眼可区分：

- 平滑追踪：明显平滑、非瞬时
- 瞬间锁定：首次获取立即甩准，后续稳定跟随
- 甩枪并回正：首次快速甩准，释放后可见地平滑回正

具体数值在实现阶段通过测试和编译验证确定，但不得让三种模式默认效果再次趋同。

## 11. 配置兼容与迁移

现有用户可能已经有旧的 Forge client config。

处理原则：

- 新配置项使用新的键名并提供默认值。
- 旧 `TARGET_MODE` 可以暂时保留为兼容读取，但新 UI 不再直接使用它；首次加载时可将旧模式映射到三个布尔类别：
  - HOSTILE_ONLY → 仅敌对怪物
  - MOBS_ONLY → 敌对怪物 + 其他生物
  - ALL_LIVING → 玩家 + 敌对怪物 + 其他生物
- 旧 `STICKY_TARGET` / `SWITCH_HYSTERESIS` 可保留一个版本作为迁移来源，但新逻辑以粘滞强度和切换确认时间为准。
- 旧 HUD 坐标不存在时使用默认位置。

不要求自动删除旧配置键，避免 Forge 配置迁移引发不必要风险。

## 12. 性能约束

300 方块搜索范围可能包含大量实体，因此不能每 tick 对所有实体做昂贵检查。

策略：

- 无目标时允许按固定间隔全量搜索。
- 有稳定目标时，主要验证当前目标状态。
- 替代候选扫描按较低频率进行，例如每 2～4 tick 一次，而不是每 tick 全量扫描。
- 只有通过便宜的类型、存活、距离、FOV 过滤后，才进行可见性射线等较贵操作。
- 候选确认需要跨 tick 状态，不要求每 tick 找出全世界绝对最优目标。

## 13. 测试策略

### 13.1 纯逻辑测试

将以下逻辑尽量抽成无 Minecraft 依赖或低依赖的纯逻辑组件：

- 粘滞强度到切换阈值的映射
- 候选连续确认计数
- 候选丢失后确认计数清零
- 当前目标失效立即解锁
- 搜索 FOV / 脱锁 FOV 双阈值
- 三种自瞄模式状态转换
- 角度平滑与最大转向限制
- HUD 归一化坐标钳制
- 旧 TargetMode 到新组合布尔值的迁移映射

### 13.2 行为测试

至少覆盖：

1. 两个目标交叉时不会快速来回切换。
2. 新目标短暂更优但不足 12 tick 时不切换。
3. 新目标持续明显更优时最终允许切换。
4. 当前目标死亡后立即重选。
5. 当前目标短暂被遮挡不会马上丢失。
6. 盔甲架永远不会成为目标。
7. 标准防假人会过滤没有正常 PlayerInfo 的 Player 实体。
8. 三个目标类别可以任意组合。
9. SNAP 只在首次获取时瞬间甩准。
10. FLICK_RETURN 释放后回到触发前视角。
11. 总开关键关闭时立即停止自瞄。
12. HUD 坐标拖动后保存并能恢复。

### 13.3 构建验证

最终必须运行完整：

```text
gradle clean build --stacktrace --no-daemon
```

并通过 GitHub Actions 的 Forge 1.20.1 云编译后，才生成并交付最终 JAR。

## 14. 完成标准

本功能只有在以下条件同时满足时才算完成：

- 默认情况下锁定不再频繁换人。
